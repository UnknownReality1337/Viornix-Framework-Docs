    API Reference

    Viornix:AddServices(path: Folder, callback: boolean)

    Adds all services located within the specified path folder.

    • Parameters:
    • path (Folder): The folder containing your service modules.

    • callback (boolean):
      When set to true, Viornix will automatically require and inject specified utilities and dependent services into your services.
      This simplifies accessing related services and utilities, enabling cleaner and more modular service code.

    • Usage:
      Call this method to register your services before initializing them with Viornix:InitializeServices().

    Viornix:AddServices(script.Parent.Main.Services, true) -- Enables callbacks and automatic injection

    Viornix:InitializeServices()

    Initializes and starts all services that were previously added using Viornix:AddServices.

    • Parameters:

    • None

    • Description:
      This method will call the Init() and Start() methods on each added service, in that order.
      Ensure that AddServices is called before this, and that your services define the Init and Start methods appropriately.

    • Usage:

    Viornix:InitializeServices()

    Viornix:AddUtilities(path: Folder)

    Registers utility modules from the given folder so they can be injected into services when callbacks are enabled.
    This must be called before any other initialization or service registration functions.

    • Parameters:

    • path (Folder): The folder containing your utility modules.

    • Description:
      When callback is set to true in Viornix:AddServices, services can define a Utilities table to specify which utilities they depend on.
      Each utility name must match the name of a ModuleScript inside the provided folder.
      These utilities will be automatically required and attached to the service for easy access (e.g. self.Utilities.YourUtility).

    • Example Usage:

    Viornix:AddUtilities(game.ReplicatedStorage.Utilities)

    Viornix:GetUtility(util: string)

    Retrieves a utility that was previously registered using Viornix:AddUtilities, allowing you to access utilities outside of services — such as in components, modules, or regular scripts.

    • Parameters:

    • util (string): The name of the utility module to retrieve. Must match the name of the ModuleScript in the utilities folder.

    • Returns:

    • The required utility module, or nil if not found.

    • Description:
      This is especially useful when you want to reuse utility functions in non-service systems, like UI components, handlers, or systems like Sprocket

    • Example Usage:

    local DataService = Viornix:GetUtility("DataService")
DataService:SaveSomething()

    Viornix:FireEvent(...)

    Acts similarly to FireServer or FireClient, but without requiring manual creation or management of RemoteEvent instances.
    If the specified event does not exist, Viornix will automatically create it for you — helping reduce boilerplate and improve maintainability.

    • 💡 Key Features:
    • 🔧 Automatically handles RemoteEvent creation.
    • 🤝 Unified, simplified syntax for both client and server.

    • ⚡ No need to define remotes manually in ReplicatedStorage.

    • 🔧 Argument Rules:

    • The first argument is always the name of the event ("Clicked" in this case).

    • If called on the server, the first argument must be the Player, followed by the event name.

    • 📦 Client Usage:

    Viornix:FireEvent("Clicked")
    • 🛠️ Server Usage:
    Viornix:FireEvent(player, "Clicked")

    Viornix:ListenEvent(event: string, callback: function)

    Registers a listener for a remote event, similar to OnClientEvent or OnServerEvent.
    Pairs with Viornix:FireEvent to handle remote communication without manually managing RemoteEvent instances.

    • 💡 Key Features:
    • 🔧 Automatically listens to remote events created via Viornix:FireEvent.
    • 🤝 Works on both client and server.

    • ⚡ No need to define or bind RemoteEvents manually.

    • 🔧 Parameters:

    • event (string): The name of the event to listen for.

    • callback (function): The function that will be executed when the event is triggered.

    • 📦 Client Usage:

    Viornix:ListenEvent("Clicked", function(arg1, arg2)
    print(arg1, arg2)
end)
    • 🛠️ Server Usage:
    Viornix:ListenEvent("Clicked", function(player, arg1, arg2)
    print(player, arg1, arg2)
end)

    🧠 This is ideal for handling game logic like button presses, UI triggers, or server signals without cluttering your code with manual RemoteEvent setup.

    Viornix:ListenInvoke(func: string, callback: function)

    Registers a listener for a RemoteFunction invocation, automatically creating and managing the remote function instance if it doesn’t exist.

    • 💡 Key Features:
    • 🔧 Automatically creates and manages RemoteFunction instances under a RemoteFunctions folder.
    • 🤝 Supports both client and server invocation handlers (OnClientInvoke and OnServerInvoke).
    • 🔄 Returns a Promise that resolves with the callback result, enabling asynchronous workflows.

    • ⚡ Simplifies remote function setup without manual binding or instance creation.

    • Parameters:

    • func (string): The name of the remote function to listen for.

    • callback (function): The function called when the remote function is invoked.

      • On the server, the first argument is the invoking player, followed by any additional arguments.
      • On the client, the callback receives all arguments sent from the server.

    • Returns:
      A Promise that resolves with the callback’s returned value.

    • 📦 Client Usage:

    Viornix:ListenInvoke("RequestClientData", function(args)
    -- Return some data to server
    return { version = "1.0.0" }
end)
    • 🛠️ Server Usage:
    Viornix:ListenInvoke("GetPlayerStats", function(player, statName)
    -- Fetch stats for player
    return { health = 100, mana = 50 }
end)

    Viornix:Invoke(func: string, ...)

    Invokes a remote function call, automatically creating the remote function if it does not exist.

    • 💡 Key Features:
    • 🔧 Automatically creates and manages RemoteFunction instances under a RemoteFunctions folder.
    • 🌐 Supports both client-to-server and server-to-client remote function calls.
    • ⚡ Simplifies invoking remote functions without manual setup or instance management.

    • 🔄 Returns the value returned by the remote function, enabling synchronous communication.

    • Parameters:

    • On the client:
      • func (string): The name of the remote function to invoke.
      • Followed by any arguments to send to the server.

    • On the server:

      • player (Player): The player to invoke the remote function on.
      • func (string): The name of the remote function.
      • Followed by any arguments to send to the client.

    • Returns:
      The value returned by the remote function call.

    • 📦 Client Usage:

    local result = Viornix:Invoke("GetPlayerStats", "health")
print(result) -- e.g., 100
    • 🛠️ Server Usage:
    local inventory = Viornix:Invoke(player, "RequestInventory")
print(inventory) -- e.g., { sword = 1, shield = 1 }
